# Next Passkey WebAuthn v0.3.0

Add passkey enrollment, username-free sign-in, and credential management to an existing Next.js App Router app with PostgreSQL. The SDK now ships a route handler, database migration, browser client, and React controls. Your app continues to own accounts, sessions, login policy, and recovery.

## Breaking upgrade: users must re-enroll

**Existing passkeys from v0.1.x and v0.2.x require re-enrollment.** v0.3.0 creates a fresh PostgreSQL schema without importing legacy credentials. Before switching sign-in, confirm that every affected user has a working sign-in or recovery method independent of their old passkey. Preserve the old credential data during rollout. After the switch, users can sign in through their fallback and enroll a new passkey in account settings. [Upgrade guide](https://github.com/shaoxuan0916/next-passkey-webauthn/blob/main/docs/quickstart.md#upgrading-from-01x-or-02x)

## What’s new

- Mount one App Router `POST` handler with `createNextPasskeys()` and connect it to your existing session reader and sign-in policy.
- Add `PasskeySignIn` and `PasskeySettings` for username-free sign-in, optional browser autofill, and enrollment, listing, renaming, and revocation. Use `createPasskeyClient()` for custom UI.
- Store credentials and verification attempts in PostgreSQL with the bundled SQL migration. This replaces the legacy Prisma and Supabase adapters and the separate challenge stores, including Redis.
- Verification attempts expire and are consumed atomically. Enrollment and sign-in require authenticator user verification. Enrollment and revocation also require a recent application sign-in.

## Integration requirements

Use Node.js 20 or later and meet your app’s Next.js requirement. Replace legacy imports and route wiring with the new package entry points, apply the PostgreSQL migration, and provide request and operation rate limits for HTTPS deployments.
